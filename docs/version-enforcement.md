# Version Enforcement

> Ensures standards and hooks have their version numbers bumped when content changes.

---

## How It Works

Standards in `standards/` have a version comment on line 1:

```markdown
<!-- standard: git | version: 1.0.0 -->
```

Hooks in `standards/hooks/` have a version comment on line 2:

```bash
#!/usr/bin/env bash
# hook-version: 1.0.0
```

Two enforcement layers prevent changes without version bumps:

1. **CI check** — fails the PR if a standard changed without a version bump
2. **Local pre-commit hook** — blocks the commit locally for fast feedback

---

## CI Workflow

**File:** `.github/workflows/standards-version-check.yml`

Runs automatically on PRs that touch `standards/` or `standards-versions.json`. The workflow:

1. For each changed `standards/*.md` file, extracts the version from the PR branch and the base branch
2. If content changed (excluding the version line itself) but the version stayed the same — **fails the check**
3. Verifies `standards-versions.json` is in sync with current standard versions

### Scripts

| Script | Purpose |
|---|---|
| `.github/scripts/check-standards-versions.sh` | Compares versions between two git refs. Reusable locally. |
| `.github/scripts/build-versions-manifest.sh` | Generates `standards-versions.json` from standard files. |
| `.github/scripts/standards-versions.json` | Generated manifest — maps standard names to current versions. |

### Running Locally

```bash
# Check your branch against main
.github/scripts/check-standards-versions.sh origin/main

# Regenerate the manifest after bumping a version
.github/scripts/build-versions-manifest.sh
```

---

## Local Pre-Commit Hook

**File:** `standards/hooks/standards/pre-commit-version-check.sh`

Blocks commits that modify `standards/*.md` files without bumping the version comment. Provides immediate feedback before you push.

### Installation

```bash
# From the claude-templates repo root:
standards/hooks/standards/install-hooks.sh

# Or install all hooks at once:
standards/hooks/install-hooks.sh
```

The installer handles three scenarios:

| Scenario | Behaviour |
|---|---|
| No existing pre-commit hook | Installs directly as `.git/hooks/pre-commit` |
| Existing versioning hook | Creates composite wrapper in `pre-commit.d/` running both |
| Composite `pre-commit.d/` already exists | Updates `02-standards-version.sh` in place (idempotent) |

## Version Manifest

**File:** `.github/scripts/standards-versions.json`

A committed JSON file mapping standard names to their current versions:

```json
{
  "git": "1.0.0",
  "operator": "1.0.0",
  "versioning": "1.0.0",
  "wiki-writing": "1.0.0",
  "workflow": "1.0.0"
}
```

This manifest is:
- Used by the [drift detection](drift-detection.md) system to compare consumer versions
- Verified by CI to stay in sync with actual standard files
- Regenerated by running `build-versions-manifest.sh`

## Version Bump Rules

| Change type | Bump | Example |
|---|---|---|
| Clarification, typo, formatting | **Patch** (0.0.x) | Fix wording in git.md |
| New section, new guidance (backwards compatible) | **Minor** (0.x.0) | Add deployment checklist to workflow.md |
| Removed or changed existing rules | **Major** (x.0.0) | Remove squash-merge requirement from git.md |

## Skill Version Auto-Bump

The pre-commit hook (`hooks/versioning/git-hook-pre-commit.sh` v1.1.0+) automatically bumps skill patch versions when SKILL.md content changes without a manual version bump.

**How it works:**
1. Detects staged `skills/*/SKILL.md` files with content changes (excluding the version line)
2. Auto-bumps the patch component (e.g. `1.1.0` → `1.1.1`)
3. Re-stages the updated SKILL.md
4. Regenerates and stages `skills-versions.json`

**Behaviour:**
- Only runs in repos with a `skills/` directory (i.e. this repo)
- Skips new skills (no HEAD version to compare against)
- Skips skills where the version was already bumped manually
- Only bumps patch — minor/major bumps remain manual

This eliminates the CI failure pattern where skill content changes and version bumps landed in separate commits.

## Hook Versioning

All hook scripts include a `# hook-version: X.Y.Z` comment on line 2. This allows tracking which version of a hook is installed in consumer projects.

| Hook type | Update mechanism |
|---|---|
| Claude Code hooks (symlinked) | Auto-update — symlinks point to this repo |
| Git hooks (copied) | Manual — re-run `install-hooks.sh` to update |

The drift detection system reminds consumers to re-run `install-hooks.sh` when drift is detected.
